# Segnali del workspace → idee di hook

Un workspace parla anche dove non ha regole scritte. Questa tabella è il contratto tra `scripts/find_opportunities.py` (che trova i segnali) e l'agente (che li trasforma in idee): stesso `signal` id, stessa idea di partenza. Ogni segnale produce un'idea **solo se supera il gate di utilità** della Fase 2 (beneficio misurabile: turni risparmiati, rischio evitato, rework evitato).

| `signal` | Evidenza cercata | Tipo | Idea di partenza | Beneficio | Trappole |
|---|---|---|---|---|---|
| `todo-file` | `TODO.md`, `todos-*.md`, `tasks.md`, `inbox.md`, `backlog.md` (conta voci e formato: checkbox / numerata / libera) | D | `todo: <testo>` → append nel formato del file, `{ drop }` con conferma; `done: <testo>` rimuove o spunta | 1 turno intero per ogni cattura (il contesto completo non viene inviato) | Prefissi da confermare con l'utente; se il file manca nella cwd, `next(e)`; match fuzzy → mai indovinare, passare al modello |
| `secrets` | `.env*` (non `.example`), `.secrets/`, `credentials*.json`, `service-account*.json`, `*.pem`, `*.key`, `id_rsa` | H | Deny su Read/Edit/Write e su Bash che legge il file (`cat`, `sed`, `grep`, `echo $VAR`); deny su `git add` che lo include; nel deny: «leggi solo i nomi: `grep -o '^[A-Z_]*=' .env`» | Segreto nel transcript o nel commit = irreversibile | Lasciare leggibili i `.example`; il modello deve poter verificare che una chiave ESISTA (nomi sì, valori no) |
| `autogenerated` | Marker in commento di testa: `auto-generated`, `do not edit`, `non editare`, `@generated`, `<!-- generated`, `TREE:START` | H | Deny su Edit/Write con il generatore nel messaggio; per Bash, deny se path + indicatore di scrittura | Zero edit persi alla rigenerazione, zero turni di rework | Il marker in prosa non conta (solo commenti / prime righe di un markdown); se il generatore non è noto, chiederlo |
| `changelog-after-commit` | `CHANGELOG.md`/`HISTORY.md` + script `*changelog*`, `generate_*`, `update_docs*` | E | Post-hook su `git commit` riuscito: `$.process.run([...])` in background; se serve giudizio, `$.prompt.submit('/commit-docs')` a fine turno | Documentazione mai indietro; il modello non deve «ricordarsi» | Script lento → fuori dal budget del dispatch: lanciare senza `await`; script che richiede giudizio non è E |
| `deploy-on-push` | `.gitmodules`, `netlify.toml`, `vercel.json`, `fly.toml`, `render.yaml`, `wrangler.toml`, `Procfile`, workflow `deploy|release|publish` | B | `$.ui.ask` prima di `git push` nella dir/submodule; dialogo chiuso = deny; ok memorizzato in `$.store` per la sessione | Deploy non voluto, quota build, rollback | La dir si riconosce da `e.command` **e** da `$.session.cwd()`; in `-p` nega sempre (giusto) |
| `package-manager` | `pnpm-lock.yaml`, `yarn.lock`, `bun.lock(b)`, `package-lock.json` | C | Rewrite `npm|yarn|npx` → gestore del lockfile; `$.ui.log` della riscrittura | Comando fallito + retry evitati; lockfile mai sporcato | Non riscrivere dentro stringhe quotate o `grep`; monorepo con più lockfile → chiedere |
| `python-interpreter` | `.venv/`, `uv.lock`, `poetry.lock`, `Pipfile.lock`, `environment.yml`, `.python-version` | C | Rewrite `python|python3|pip` → interprete del progetto quando il comando gira dalla root | `ModuleNotFoundError` + 2-3 turni di retry ogni volta | `$.fs.exists` sull'interprete prima di riscrivere; conda: il path dell'env non è nel repo, va chiesto |
| `database-file` | `*.db`, `*.sqlite`, `*.sqlite3`, `*.duckdb` | B | Gate su Bash con `DROP|DELETE FROM|TRUNCATE|ALTER|UPDATE` senza `WHERE` sul DB; Write/Edit sul file → deny | Perdita dati locale, spesso senza backup | Le `SELECT` passano; il pattern SQL è euristico: gate (ask), mai deny cieco su UPDATE |
| `status-markers` | File `*last-run*`, `*pending*`, `*queue*`, `*inbox*` (marker di cron, code da smaltire) | G | `session.start` legge i marker → `ui.render AbovePrompt` con stato + `Button` hotkey verso la skill di smaltimento; refresh con `$.clock.every` | Niente «controlla se il cron ha girato» a mano né turni per chiederlo | Solo interattivo; hotkey solo cifre; prop fuori allowlist = albero scartato |
| `formatter` | `.prettierrc`, `biome.json`, `ruff.toml`, `pyproject [tool.ruff|black]`, `eslint.config.*`, `rustfmt.toml` | E | Post-hook su Edit/Write: formatter sul solo file toccato, via `$.process.run` | Il modello non spende turni su formattazione e lint banali | Formatter, non `--fix` invasivi; escludere file generati; non su file fuori dal linguaggio |
| `git-conventions` | `.gitmessage`, commitlint, `.pre-commit-config.yaml`, `.husky/`, `PULL_REQUEST_TEMPLATE.md`, `CODEOWNERS` | F / C | `attribution.text` per firma/footer; deny su `git commit --no-verify` e `git push --force` (ammesso `--force-with-lease`) | Convenzioni sempre rispettate, check mai bypassati | Il footer di `attribution.text` sostituisce quello di default: verificare il testo con l'utente |
| `mcp-destructive-tools` | Server MCP in `.mcp.json`, `.claude/mcp.json`, `~/.claude.json` (globali e di progetto); nomi tool con `delete|trash|remove|send|publish|deploy|pay|revoke` | A / B | Deny (o `$.ui.ask`) sul nome esatto `mcp__<server>__<tool>`; il messaggio dice cosa fare invece (bozza, proposta) | Azione esterna irreversibile: email inviata, file cestinato, pagamento | Elencare i tool reali (`claude mcp list`, `$.tool.list`) prima della regex; mai deny su nomi indovinati |
| `other-agents` | `AGENTS.md`, `.cursorrules`, `.cursor/`, `copilot-instructions.md`, `.agents/`, `GEMINI.md` | N (limite) | Nessun hook: l'avviso che le regole valide anche per questi agenti restano nel file di istruzioni in una riga | — | Non presentarlo come idea |
| `large-instructions` | `CLAUDE.md` > 8 KB | — (contesto) | Misura per sezione (`context_size.py --by-section`): dice quanto vale ogni regola spostata | Token fissi a ogni turno di ogni sessione | La misura è ~4 caratteri/token: ordine di grandezza |

## Segnali dallo storico d'uso (`scripts/scan_history.py`)

Legge i transcript locali del progetto (`~/.claude/projects/<cwd>/*.jsonl`), in sola lettura; nel report finiscono conteggi e pattern normalizzati, mai conversazioni intere. Se la cartella non esiste (workspace nuovo) la fase si salta e nulla dipende da lei.

| Cosa misura | Tipo | Idea | Come si stima il beneficio |
|---|---|---|---|
| Prompt brevi ripetuti (≤ 8 parole, ≥ 2 volte; esclusi ack come «sì», «fatto», «vai») | D | Alias `prompt.submit` → rewrite verso una skill (`/commit`), oppure `{ drop }` se l'azione è deterministica | volte/mese × 1 turno |
| Prefissi `parola:` usati come comando («capture:», «nota:», «done:») | D | Hook `prompt.submit` che agisce senza modello | volte/mese × 1 turno |
| Slash command frequenti (≥ 3) | G | `Button` con hotkey nella band `AbovePrompt`, o alias | tempo, non token |
| Comandi Bash che falliscono più volte con la stessa testa (`python …`, `npm …`, `sqlite3 …`) | C | Rewrite verso interprete/gestore giusto, o deny con l'istruzione corretta | errori/mese × 2-3 turni di retry |
| Passo fisso ripetuto subito dopo `git commit` (esclusi push/status/log/diff/add) | E | Post-hook che lo lancia senza turno | volte/mese × 1 turno |
| Tool MCP a nome distruttivo/outbound **già invocati** | A / B | Deny o `$.ui.ask` sul nome esatto: non è più un'ipotesi, è un rischio osservato | costo dell'azione × frequenza |

Il **costo di un turno** per il calcolo dei token = `context_size.py CLAUDE.md` (token stimati) + le altre istruzioni caricate a ogni turno (skill description, memoria): è la cifra che l'hook D fa risparmiare ogni volta che droppa un prompt.
